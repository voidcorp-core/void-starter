# Fast CI by default: affected graph, main-seeded cache, sharded browser tests

## Context

Rekalibr, generated from this starter, pays 27 to 40 minutes of CI per pull request (DEV-1270).
The generic causes live in the starter workflow (DEV-1271):

- The bun and Turbo caches shared one key, `hashFiles('bun.lock')`. A cache key is never
  overwritten, so `.turbo` stayed frozen at the first run after each lockfile change and the
  hit rate decayed with every merge. Restoring by prefix also carried every older entry forward.
- Every pull request ran the whole Turbo graph, then the browser suite only after `code`
  finished, on one runner.
- `@repo/factory#test` reads `.github/workflows/ci.yml` and `biome.json` outside its package.
  Turbo did not hash them, so a workflow change replayed the CI contract test from cache.

This record amends one ordering of `adr:412129ca-2f58-4047-9e3c-e6a114a1b590`: `e2e` no longer
waits for `code`. Its independent security checks and aggregated `quality` gate are unchanged.

## Decision

Pull requests run the affected Turbo graph from a Turbo cache that only `main` pushes save,
pruned to the tree they hashed, while the browser suite runs in Playwright shards alongside
the code checks behind the unchanged required `e2e` check.

- **Scope.** `.github/scripts/ci-scope.mjs` narrows to `--affected` only for a pull request
  whose merge commit and diff are readable and whose changed paths are all inside workspace
  packages or documentation. Push, merge queue and manual runs, any other path (lockfile,
  manifests, `turbo.json`, `.github/**`, root configuration) and any read failure run the full
  graph. Turbo widens further on its own global inputs and on a too shallow checkout.
- **Cache.** Turbo cache key `<os>-turbo-<sha>`, restored by prefix; bun cache keyed by the
  lockfile. Only a `main` push saves, after `.github/scripts/ci-cache.mjs prune` deletes every
  entry its run summary did not hash. Pull requests and merge groups restore only.
- **Browser tests.** A matrix `e2e-shard` job runs `--shard=i/n` with the blob reporter, in the
  official Playwright image at the version `bun.lock` resolves (`.github/scripts/ci-versions.mjs`),
  so no apt mirror sits on the path of a required check; the
  `e2e` job keeps the required check name, rejects any non-success shard result, and merges the
  blob reports into one HTML report when a shard failed.
- **Task inputs.** Tests that read root files declare them with `$TURBO_ROOT$`.

## Consequences

Positive:

- A pull request touching one module rebuilds only that module and its dependents, and restores
  the rest of the graph from the latest `main` tree instead of an arbitrary older one.
- The browser suite no longer adds its full duration after `code`; its runtime splits by shard.
- The seed stays bounded to one tree; old seeds age out of the GitHub quota first.
- The CI contract test re-runs whenever the workflow changes.

Negative:

- Each `main` push saves one Turbo seed (the size of one tree's outputs).
- Two browser runners instead of one; a failing suite costs a merge-reports install.
- A test that reads an undeclared file outside its package can be skipped by `--affected` or
  replayed from cache. The rule is to declare such inputs with `$TURBO_ROOT$`.

## Alternatives considered

- **Keep the lockfile cache key.** Free, but the frozen `.turbo` is the decay this record fixes.
- **Save the cache from pull requests too.** Measured in Rekalibr (DEV-1270): a 1.6 GB upload per
  lockfile change that evicted the base seeds, while another pull request can never restore it.
- **Vercel Remote Cache.** Best hit rate, but a token or OIDC policy and an external account in
  every generated project; documented as an opt-in in `docs/CI.md` instead.
- **`playwright install --with-deps chromium` on the runner.** 22 to 40 s on a good day, against
  about 41 s to start the image in Rekalibr. But its apt mirror took 4.5 min on 2026-10-22 and
  failed both shards of the first run of this change on 2026-11-11 (DNS failure resolving
  `azure.archive.ubuntu.com`, 10 min lost). A required check must not depend on it.
- **Cache the browser binary.** Playwright advises against it; system libraries still need apt.
- **Filter on paths in `on:`.** A filtered workflow leaves required checks pending forever.
- **Narrow the merge queue run.** The merge group is the last gate before `main`; it stays full
  and fast through the same cache.

## Reversal cost

Low. Reverting the workflow, the scripts and the Playwright reporter restores the previous
serial pipeline; required check names and branch protection do not change.
